**引用时必须同时带的两条限制：**

1. 子采样按缺陷密度整组选取，密度被抬高（某片 0.10 → 0.32），因此**绝对召回率不可与全量运行比较**，只能用于两臂之间的对照；两臂差别仅在「三个 Reader 是否重复读同一批」，收益来自**联合覆盖**而非单文件精度。
2. n=5 时双侧检验的最小可达 p 值为 0.0625，**数学上不可能 < 0.05**；本项目假设有方向性，故按单侧报告，并同时给出双侧值供核对。
3. **E3b 的效应落在机制层而非结果层**：共享记忆使冗余率升、K\* 降（5/5），但召回无损失——语料偏简单导致天花板。**不得写成「共享降低检出率」**。

## 5. 一次性结论与限制（避免误引）

- `capacity-and-faults.json` 的 33.92 rps 是**单机、600 请求、短时**探针，**不能**当并发能力或生产容量。
- `blind-arbitration.json` 与 `gap-attribution.json` 的 A/B 部分是**规则替身与伯努利采样**，结论是方向性的。
- `independence-gate.json` 使用合成证据 + 完美检出 Reader，只验证「指标 → 判定 → 处置」的接线。
- `distributed-tx.json` 是协议模拟，**不是**真实两阶段提交。
- `catalog.json` 记录于 MySQL 8.0.19 时期；8.4.0 的完整验收看 `mysql-runtime.json`。
- 真实模型仲裁已补测（`blind-arbitration-llm.json`）；两条未检出（J1 转账先扣款、J4 吞异常返回 0）属模型能力限制，不代表协议无效。
