## 3. 关键新发现：单 Agent 基线（S4，chat）

| 配置 | 覆盖 | 召回 | 调用 | 成本 |
| --- | ---: | ---: | ---: | ---: |
| 单 Agent 一次读全部 26 文件 | 26 | **6/12** | 2 | ¥0.82 |
| 单 Agent 分 5 批顺序读 | 26 | **10/12** | 5 | **¥1.60** |
| 3 Agent 分散 | 26 | **10/12** | 6 | ¥2.80 |
| 3 Agent 集中 | 9 | 3/12 | 6 | ¥2.80 |

**这是本次最重要的结论，也是唯一能对外主张的「更优」：**

- **有界分批 > 一次性全量投喂**：10/12 vs 6/12。原因可解释——26 文件一次调用只吐 5,144 token（198/文件），分 5 批吐 9,971 token（384/文件）。瓶颈是**输出容量**，不是上下文长度。
- **多 Agent vs 单 Agent 分批：打平（10 = 10），且单价高 43%。**「多智能体」目前不是差异化优势。

$env:PARALLAX_MAX_EVIDENCE_PER_CALL='30'   # 单上下文基线必须先设这个
run_slice.py --task S4 --out p6-single-context/S4 --model deepseek-chat --arms blind_no_coverage --readers 1

## 4. 必须随数字一起写的限制

1. **语料偏简单**：S4 全读臂里 12 条缺陷中 **10 条被 3 个独立读者全部找到**、2 条 0/3。中间档为空 → 缺陷两极分布。
2. **子采样抬高密度**：S6 从 0.10 抬到 0.32，**绝对召回不可与历史全量运行比较**。
3. **邻近匹配口径**：召回靠路径 + 行号 ±25。S2 人工核实 8 条命中里 **7 真 1 假**，绝对召回高估约 10 个百分点。
4. **范围内召回不是 100%**：平均约 72%（50%–100%），读到文件后仍会漏，但两臂各有胜负。
5. n=1 的结论（E3、单 Agent 基线）只能作方向性观察。
